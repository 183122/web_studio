# ADR-0010: AI generation pipeline (plan → compile → propose → approve)

- Status: Accepted (Phase 3)
- Context: spec §0.7 and §11 — AI output is untrusted, must never execute, must not corrupt the schema, must show a plan, changes, cost and permission impact before applying, and needs a safe fallback.
- Decision:
  1. **Intent, not structure.** The model answers with a compact *plan spec* (pages → section kinds, entities → fields, permissions, workflows, open questions, assumptions, confidence) or an *edit spec* (setText, setStyle, setTheme, addSection, removeComponent, addField, renamePage). It never emits component trees, ids, commands, HTML or code. Both are enforced with structured outputs (JSON Schema).
  2. **Untrusted-output normaliser** (`SpecNormalizer`) clamps counts/lengths, strips control characters, drops unknown kinds/types/fonts, validates colours and links, and turns names into safe identifiers.
  3. **Deterministic compiler** (`AppSpecCompiler`) maps specs to the same allowlisted typed commands as the visual editor, with registry defaults and canonical value checks; unsupported pieces are skipped with a warning shown to the user. Edits are confined to the selected component/page subtree (partial regeneration).
  4. **Dry run + repair**: commands are applied to a copy of the current head and validated with the canonical validator. If a plan does not compile cleanly, concrete issues are sent back to the model (max `repair_attempts`, within the credit budget).
  5. **Human approval twice**: the user approves the plan, then reviews a proposal (pages, models, permission impact, workflows, before/after edits, warnings, command count) and applies or rejects it. Applying goes through the normal write path (optimistic concurrency, full validation, asset ownership) and creates an `ai` checkpoint, so it can be undone from version history. Proposals expire after 24 h.
  6. **Gateway**: Claude Opus 5.5 through the official Anthropic PHP SDK (effort `medium`, server-side refusal fallback beta), typed exception mapping; transient failures (429/5xx/overloaded/timeout/connection) fall back to an **offline rules provider** that answers the same schema from keyword templates and is labelled as non-AI. Refusals, auth errors, invalid or truncated output are reported, never retried silently.
  7. **Governance**: explicit consent before sending text to an external provider; prompts stored only PII-redacted (+ hash); per-request model, tokens, cost and credits; monthly credits from plan entitlements, reserved under an organisation lock and committed from actual usage; BYOK keys encrypted with the app key and never returned; isolated `ai` queue; 6 requests/min/user.
- Consequences: the model cannot produce anything the editor could not produce; quality of generated *content* depends on the model, but safety and integrity do not. OpenAI/Gemini adapters fit the `AiProvider` interface but are not implemented yet.
