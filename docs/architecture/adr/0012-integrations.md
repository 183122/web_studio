# ADR-0012: Google integrations, sync engine and outbound webhooks

- Status: Accepted (Phase 5)
- Context: spec §10, M22–M25, J4/J5. Google data must stay least-privilege, tokens must never leak, sync must survive quotas/outages, and Google Sheets must not become the transactional database. Outbound calls to user URLs are an SSRF vector.
- Decision:
  1. **One connection per workspace (M22)**, granted explicitly by a workspace admin through the authorization-code flow with **PKCE (S256)** and a single-use `state` bound to the user (10 min TTL, cache). Only the features the admin ticks are requested: `spreadsheets` for Sheets, **`drive.file`** for Drive (the app sees only files/folders it created). Refresh and access tokens are encrypted at rest (`encrypted` cast), hidden from serialization, refreshed under a per-connection lock; `invalid_grant`/401 marks the connection `revoked`. Disconnect revokes at Google (best effort), deletes tokens locally and moves the workspace's syncs to `disconnected`. The client ID/secret come from env or the platform-admin settings (Phase 4.5).
  2. **Google calls** go through `GoogleClient`, which classifies failures (`auth`, `permission`, `not_found`, `rate_limited`, `transient`, `invalid`, setup errors) into `GoogleApiException`; the API renders them as `google_<kind>` with actionable Thai messages and never includes tokens or raw bodies.
  3. **Sheets sync (M23)** — the app DB is canonical. A sync maps model fields ↔ column headers of one tab, per environment. Pull validates every row with the same `RecordInput` rules as forms/CSV (invalid rows reported, valid rows applied), identifies rows by `_studio_id` then an optional key field (idempotent upsert), and never runs workflows. Push writes `valueInputOption=RAW` (no formula evaluation), adds missing header columns at the end, updates only mapped cells whose value changed, appends new records and never deletes sheet rows. Two-way sync keeps per-row hashes of the last synced values (`sheet_sync_rows`); a row changed on both sides is a conflict resolved by `app_wins` / `sheet_wins` / `skip`. Limits: 5,000 rows, 52 columns.
  4. **Jobs**: `integration_sync_jobs` record every run (trigger, attempts, stats, row errors). Runs are queued on `google`, serialized per sync by a lock, retried on rate limits/outages with backoff 30 s → 2 min → 10 min → 30 min, then **dead-lettered** (`dead`) and retryable from the UI. A scheduler queues due syncs (15 min … daily).
  5. **Drive attachments (M24)** — a per-project folder created by the app; files are validated by content sniffing (allowlist; no HTML/SVG/scripts/executables), size-capped (10 MB), malware-scanned, uploaded with `appProperties`, and referenced in `record_attachments`. Every download re-checks the file at Google and the caller's project permission; deleted files become `missing`, revoked access `access_lost`. Downloads are proxied with `Content-Disposition: attachment` and `nosniff`.
  6. **Webhooks (M25)** — per-project endpoints per environment subscribe to `record.created|updated|deleted`. Deliveries are queued after commit on `webhooks`, signed `X-Studio-Signature: t=<unix>,v1=HMAC-SHA256(secret, "t.body")` with `X-Studio-Event-Id` for idempotency, retried with backoff (10 s … 2 h, 6 tries), dead-lettered and redeliverable; 410 or 15 consecutive dead deliveries disable the endpoint. `EgressGuard` enforces https, ports 443/80/8443, no URL credentials, and public addresses only (blocks loopback, RFC1918, link-local/metadata, CGNAT, ULA, multicast, reserved); the connection is pinned to the validated IP (`CURLOPT_RESOLVE`) and redirects are not followed.
  7. **Testing without Google**: PHPUnit uses an in-memory fake behind `Http::fake`; Playwright runs a local fake Google (`tests/e2e/fake-google`) selected by `GOOGLE_FAKE_BASE`, which the app refuses in production. The fake verifies PKCE like Google does.
- Consequences: no Google Picker yet (Sheets are linked by URL; Drive folders are app-created), no incremental authorization (reconnect to add a feature), no Sheets → app deletes. Real Google behaviour (quotas, OAuth verification for sensitive scopes) must be validated against Google before launch — see `docs/runbooks/google-oauth-review.md`.
